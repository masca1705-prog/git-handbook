01

Git과 GitHub 개념

작업 전에 알아야 할 기본 용어입니다.

Git
파일 변경 이력을 기록하는 분산 버전 관리 도구입니다. 커밋과 브랜치를 관리합니다.
GitHub
Git 저장소를 온라인에서 공유하고 Pull Request(PR)로 검토·병합하는 협업 서비스입니다.
origin
원격 저장소의 별명입니다. 보통 GitHub 저장소를 가리킵니다.
main
팀에서 통합된 코드를 관리하는 기준 브랜치입니다.
origin/main
마지막 fetch 등으로 갱신한 원격 main의 로컬 추적 참조입니다.
Local / Remote
Local은 내 컴퓨터의 저장소, Remote는 GitHub 같은 원격 저장소입니다.
feature/브랜치명
특정 기능을 작업하는 브랜치입니다. 예: feature/main-header
Working Tree / Staging / Commit
파일 수정 → 커밋 대상 선택 → 로컬 변경 이력 기록의 세 단계입니다.
02

GitHub 프로젝트 처음 내려받기

원격 저장소를 내 컴퓨터로 처음 복제합니다.

프로젝트 복제 실행 순서
명령어 기능
cd /c/workspace 프로젝트를 저장할 폴더로 이동
git clone 저장소URL GitHub 저장소와 커밋 이력 복제
cd 저장소명 복제된 프로젝트 폴더로 이동
git status 현재 브랜치와 변경 상태 확인
git remote -v 원격 저장소 주소 확인

영어 뜻과 원리

cd = Change Directory
현재 작업 폴더를 변경합니다.
clone = 복제하다
저장소의 파일과 커밋 이력을 복제합니다.
remote = 원격 / -v = verbose(상세)
등록된 원격 저장소 이름과 URL을 출력합니다.
실행 결과 및 주의사항

프로젝트 폴더와 .git 저장소가 생성되고, 일반적으로 origin도 자동 등록됩니다. 복제한 저장소에서 git init이나 git remote add origin을 다시 실행할 필요는 없습니다.

03

main 최신화 후 새 작업 브랜치 생성

최신 main을 기준으로 새 작업을 시작합니다.

실행 전 조건 커밋하지 않은 변경 사항을 먼저 정리합니다.
새 브랜치 생성 실행 순서
명령어 기능
git status 변경 사항과 현재 브랜치 확인
git switch main 로컬 main으로 이동
git pull origin main 원격 main의 최신 코드 반영
git switch -c feature/main-header 새 작업 브랜치 생성 후 이동
git branch 현재 브랜치 확인

영어 뜻과 원리

switch = 전환하다
현재 브랜치를 변경합니다.
-c = create(생성)
새 브랜치를 생성합니다.
pull = 끌어오다
원격 변경 내용을 가져와 현재 브랜치에 통합합니다.
branch = 가지
기능별로 독립적인 작업 흐름을 관리합니다.
실행 결과 및 주의사항

git branch에서 별표(*)가 붙은 브랜치가 현재 작업 브랜치입니다. 이미 존재하는 브랜치로 이동할 때는 git switch 작업브랜치명을 사용합니다.

04

변경 내용 스테이징과 커밋

수정한 파일을 선택하고 로컬 이력으로 기록합니다.

변경 사항 기록 순서 — A 또는 B 선택
명령어 기능
git status 수정 파일 확인
방법 A git add . 현재 폴더 아래 변경 사항 전체 스테이징
방법 B git add 파일명 지정한 파일만 스테이징
git status 커밋할 파일 확인
git commit -m "설명" 스테이징된 변경 사항 커밋

영어 뜻과 원리

add = 추가하다
변경 사항을 스테이징 영역에 올립니다.
commit = 기록하다, 확정하다
스테이징된 변경 사항을 로컬 이력으로 기록합니다.
-m = message(메시지)
커밋 메시지를 직접 지정합니다.
. = 현재 폴더
현재 폴더를 기준으로 변경 사항을 선택합니다.
선택 명령어 및 주의사항

git add .과 git add 파일명은 순서대로 실행하는 명령어가 아닙니다. 필요한 방법 하나를 선택합니다. 커밋은 로컬 저장소에 기록되며, GitHub로 전송되지는 않습니다.

05

새 브랜치를 처음 푸시할 때

로컬 커밋을 GitHub에 전송하고 추적 연결을 설정합니다.

첫 푸시 실행 순서
명령어 기능
git status 현재 브랜치와 변경 사항 확인
변경 시 git add . 변경 사항 스테이징
변경 시 git commit -m "설명" 변경 사항 커밋
git push -u origin "푸시할 작업 브랜치 이름" 첫 푸시 및 원격 추적 연결 설정

영어 뜻과 원리

push = 밀어 올리다
로컬 커밋을 원격 저장소로 전송합니다.
-u = set-upstream
현재 브랜치의 원격 추적 연결을 설정합니다.
origin
전송할 원격 저장소 이름입니다.

GitHub에서 PR 생성하기

  1. GitHub 저장소 페이지를 엽니다.
  2. Compare & pull request 또는 New pull request를 선택합니다.
  3. base는 main, compare는 내 작업 브랜치인지 확인합니다.
  4. 제목과 변경 내용을 작성하고 PR을 생성합니다.
  5. 팀의 리뷰와 검사를 거쳐 PR을 병합합니다.
실행 결과 및 주의사항

GitHub에 작업 브랜치가 생성되거나 갱신됩니다. 이미 커밋한 경우 add와 commit을 다시 실행할 필요가 없습니다. Push만으로 main에 병합되는 것은 아닙니다.

06

같은 브랜치에서 다시 푸시할 때

첫 푸시 이후 추가 수정 사항을 반영합니다.

추가 푸시 실행 순서
명령어 기능
git status 수정 파일과 현재 브랜치 확인
git add . 변경 사항 스테이징
git commit -m "설명" 추가 변경 사항 커밋
git push 추적 연결된 원격 브랜치로 전송

첫 푸시와 추가 푸시의 차이

첫 푸시
git push -u origin 브랜치명으로 원격 추적 연결을 설정합니다.
추가 푸시
추적 연결이 설정되어 있으면 일반적으로 git push만 사용합니다.
실행 결과 및 주의사항

새로운 커밋이 GitHub의 작업 브랜치에 반영됩니다. 이미 커밋한 경우 push만 실행하면 됩니다. 원격에 다른 새 커밋이 있다면 푸시가 거부될 수 있습니다.

07

현재 작업 브랜치에 최신 main 반영

팀의 최신 main 변경 사항을 내 작업 브랜치에 합칩니다.

실행 전 조건 현재 브랜치가 내 작업 브랜치인지 확인하고, 미커밋 변경 사항은 커밋하거나 stash로 보관합니다.
최신 main 반영 순서
명령어 기능
git status 현재 브랜치와 작업 상태 확인
git fetch origin 원격 저장소의 최신 커밋과 참조 가져오기
git merge origin/main 최신 main을 현재 브랜치에 병합
git status 병합 완료 또는 충돌 여부 확인

병합 결과에 따른 실행 흐름도

영어 뜻과 원리

fetch = 가져오다
원격 저장소의 최신 정보를 가져오지만 현재 작업 파일에 바로 병합하지 않습니다.
merge = 병합하다
지정한 브랜치의 변경 내용을 현재 브랜치에 합칩니다.
origin/main
원격 main을 추적하는 로컬 참조입니다.
conflict = 충돌
Git이 자동으로 합칠 수 없어 직접 수정해야 하는 상태입니다.
충돌 시 주의사항

충돌 파일을 수정한 뒤 git add로 해결을 표시하고, git status로 남은 충돌이 없는지 확인합니다. 일반적인 충돌 병합은 git commit으로 완료합니다. 병합을 취소하려면 진행 중에 git merge --abort를 사용할 수 있습니다.

08

작업 중 다른 브랜치로 이동할 때

미커밋 변경 사항을 임시 보관하고 복원합니다.

임시 보관과 복원 순서
명령어 기능
git status 미커밋 변경 사항 확인
git stash push -u -m "임시 저장" 변경 사항과 추적되지 않은 일반 파일 임시 보관
git stash list 임시 보관 목록 확인
git switch main main으로 이동
git pull origin main 로컬 main 최신화
git switch 작업브랜치명 원래 작업 브랜치로 복귀
git stash list 복원할 stash 항목 확인
git stash pop 가장 최근 stash 복원
git status 복원 상태와 충돌 여부 확인

영어 뜻과 원리

stash = 임시로 숨겨 보관하다
커밋하지 않은 변경 사항을 잠시 보관합니다.
push = 넣다 / pop = 꺼내다
stash 목록에 저장하거나 복원합니다. GitHub로 전송하는 push와는 다른 기능입니다.
-u = include untracked
Git이 추적하지 않는 일반 파일도 포함합니다. 무시된 파일은 포함하지 않습니다.
-m = message / list = 목록
설명을 붙이거나 저장된 stash 항목을 조회합니다.
실행 결과 및 주의사항

git stash pop은 기본적으로 가장 최근 항목을 복원합니다. 다른 항목을 복원하려면 정확한 stash 항목을 지정해야 합니다. main을 pull해도 원래 feature 브랜치에 최신 main이 자동 병합되지는 않습니다. 필요하면 07번 절차를 별도로 진행합니다.

09

PR 병합 후 브랜치 정리

GitHub에서 PR 병합과 원격 브랜치 삭제가 끝난 상황입니다.

PR 병합 후 정리 순서
명령어 기능
git status 브랜치 이동 전 변경 사항 확인
git switch main 로컬 main으로 이동
git pull origin main PR이 병합된 최신 main 반영
git fetch --prune origin 삭제된 원격 브랜치의 추적 참조 정리
git branch -r 남아 있는 원격 추적 브랜치 확인
git branch -d 작업브랜치명 병합 여부를 검사해 로컬 브랜치 삭제
git branch 남아 있는 로컬 브랜치 확인

영어 뜻과 원리

prune = 가지치기
원격에서 사라진 브랜치의 오래된 추적 참조를 정리합니다.
-r = remote
원격 추적 브랜치 목록을 출력합니다.
-d = delete
안전성 검사를 거쳐 로컬 브랜치를 삭제합니다.
실행 결과 및 주의사항

git branch -d는 GitHub 원격 브랜치를 삭제하지 않습니다. squash merge 후에는 PR이 병합되었더라도 로컬 브랜치 삭제가 거부될 수 있습니다. 보존할 커밋을 확인하지 않고 git branch -D로 강제 삭제하지 않습니다.

10

현재 Git 상태와 연결 정보 확인

필요할 때 각각 실행하는 조회 명령어입니다.

Git 상태 확인 명령어
명령어 기능 및 실행 결과
pwd 현재 작업 폴더 경로 출력
ls 파일과 폴더 목록 출력
git status 현재 브랜치와 변경 상태 표시
git branch 로컬 브랜치 목록 표시
git branch -a 로컬과 원격 추적 브랜치 목록 표시
git remote -v 원격 저장소의 fetch/push 주소 출력
git log --oneline -5 최근 커밋 최대 5개를 한 줄씩 표시

영어 뜻과 옵션

pwd = Print Working Directory
현재 폴더 경로를 출력합니다.
ls = List
파일과 폴더 목록을 출력합니다. ls -a는 숨김 항목도 표시합니다.
status = 상태
작업 트리와 스테이징 상태를 표시합니다.
branch = 가지 / -a = all(전체)
브랜치 목록을 표시합니다.
remote = 원격 / -v = verbose(상세)
원격 저장소 이름과 URL을 표시합니다.
log = 기록 / --oneline = 한 줄 / -5 = 최대 5개
최근 커밋을 간단히 표시합니다.
실행 결과

현재 폴더, 브랜치, 수정 파일, 원격 연결 주소와 커밋 이력을 확인할 수 있습니다. 이 절의 명령어는 작업 파일을 변경하지 않습니다.

기억할 순서: 상태 확인 → 안전하게 작업 → 결과 확인

Git 명령어는 현재 저장소 상태에 따라 실행 결과가 달라질 수 있습니다.
